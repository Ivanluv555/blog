你坐在电脑前，双击一个浏览器图标。过了一会儿，浏览器窗口出现了。

这看起来只是一次简单的鼠标操作。但就在这短短的过程里，计算机内部已经发生了许多事情：输入设备发出了信号，操作系统找到了程序，存储中的内容被读取到内存，处理器开始执行指令，图形系统最终让窗口显示在屏幕上。

我们每天都重复这样的操作，却很少追问：硬盘明明保存着程序，为什么还需要内存？CPU 这么小，究竟怎么「运行」一个程序？

这一篇不要求你学习电路设计或背诵大量硬件型号。我们只做一件事：沿着「打开一个程序」这条线索，建立对计算机组成与运行过程的整体理解。

## 1 先记住计算机的四类重要角色

可以把一台计算机先简化成几个彼此配合的部分：

| 组成部分 | 可以先这样理解 | 典型任务 |
| :-: | :-: | :-: |
| CPU（中央处理器） | 执行指令、处理运算并参与控制 | 计算、判断、执行程序指令 |
| 内存（RAM） | 程序运行时快速访问的工作空间 | 保存正在使用的指令与数据 |
| 持久存储 | 断电后通常仍能保存内容的地方 | 保存系统、应用、照片、文档 |
| 输入 / 输出设备 | 计算机与外部世界交互的途径 | 键盘、鼠标、屏幕、网络接口等 |


还有一个贯穿其中的重要角色：操作系统。它不是一个单独的硬件部件，而是帮助应用管理处理器、内存、文件、设备等资源的软件系统。

不要被「CPU 是大脑、内存是桌面、硬盘是仓库」这些比喻完全限制住。它们可以帮助入门，却不能代替真实机制：CPU 不会像人一样理解文字，内存也不是只用来摆放文件。

二、计算机为什么离不开二进制？

计算机中的电路擅长区分不同的电信号状态。工程上，常把逻辑状态抽象成 0 和 1，并通过许多这样的状态表示信息。

一个 bit 只表示两种可能状态；多个 bit 组合起来，就能表示更多数值。例如，8 个 bit 能表示 256 种不同的组合。
二进制 00000000  → 十进制 0
二进制 00000001  → 十进制 1
二进制 00000010  → 十进制 2
二进制 00000101  → 十进制 5
所谓「计算机只认识 0 和 1」，并不意味着电脑里的所有部件只有两个物理状态，而是说数字系统用有限的逻辑状态来编码和处理信息。

在上一课，我们看到文字、图片、音频都可以编码成字节。这一次再进一步：程序的指令也能编码成二进制信息。

于是，计算机有了一种非常强大的能力：既可以保存数据，也可以保存描述「如何处理数据」的程序。
三、冯·诺依曼思想：指令和数据都能放在存储器里
学习计算机组成原理时，你很容易遇到一个名字：冯·诺依曼体系结构（von Neumann architecture）。

入门阶段，可以抓住其中最重要的思想之一：存储程序。程序的指令可以像数据一样被存入存储器，处理器从存储器获取指令并执行。

下面是一个概念示意，不是现代计算机的精确硬件布线图：
             ┌─────────────────┐
             │    输入 / 输出   │
             │ 键盘、屏幕、网络  │
             └────────┬────────┘
                      │
     ┌────────────────┴───────────────┐
     │                                │
┌────▼────────┐                 ┌─────▼───────┐
│ CPU 处理器  │ ◄─────────────► │   内存 RAM  │
│ 控制 + 运算 │   指令与数据     │ 正在使用的信息│
└─────────────┘                 └─────▲───────┘
                                     │
                               ┌─────▼────────┐
                               │ SSD / 硬盘   │
                               │ 持久保存内容 │
                               └──────────────┘
现实中的处理器还有缓存，设备通过各种控制器与互连机制通信，GPU 可能承担大量图形和并行计算任务，不同硬件并不会都按照这张简图直接相连。

不过，这张图足够说明我们最初的疑问：为什么 CPU、内存和存储需要彼此配合？
四、CPU 真正在做什么？
CPU 的工作并不是「理解」一个应用程序想表达什么。它执行的是按照处理器所支持的**指令集（ISA）**编码的一系列机器指令。

这些指令可能涉及：
- 从寄存器或内存取得某些数据。
- 进行加法、比较等运算。
- 根据条件决定下一条指令的位置。
- 将计算结果写回寄存器或内存。
- 在必要时与操作系统、设备交互。
一个帮助理解的基础模型叫取指—译码—执行：
1. 取指（fetch）：取到下一条需要执行的机器指令。
2. 译码（decode）：识别指令要求做什么。
3. 执行（execute）：通过处理器内部部件完成相应操作。
取得指令 → 解释指令 → 执行操作 → 继续下一条
这是一种教学上的简化。现代 CPU 会采用流水线、乱序执行、分支预测、多个核心等复杂设计，不必认为它总是严格地「执行完一条才开始下一条」。
CPU 里的「小本子」：寄存器
寄存器（register）是处理器内部非常快速、容量很小的存储位置。它可以暂时保存操作数、地址或执行状态。

可以想象 CPU 正在计算 3 + 5：它需要能够取得数字，进行运算，再把结果放到某个地方。寄存器经常参与这样的过程。

CPU 并不是每做一次加法都必须先去 SSD 上找数据，因为那样会很慢。
五、为什么明明有硬盘，还需要内存？
存储设备与内存的分工，主要涉及速度、容量、成本和数据保持方式之间的取舍。

一般来说：
- SSD/HDD 更适合长期保存大量内容。
- RAM 通常提供处理器运行程序所需的快速、可随机访问的工作空间。
- CPU 内部缓存和寄存器容量更小，但能够更快地提供数据。
可以粗略把它看成一个层次：
速度通常更快、容量通常更小
         CPU 寄存器
              ↓
         CPU 缓存
              ↓
         内存 RAM
              ↓
         SSD / HDD
速度通常更慢、容量通常更大
这里的「更快」是总体趋势，不表示每种设备在所有场景下都有严格固定的速度关系。

注意： 普通 RAM 中的数据在断电后通常不会持久保留；而 SSD/HDD 的主要目的之一就是持久保存。所谓「电脑内存 16 GB」与「硬盘 1 TB」，表示的是两种不同的资源，不能简单相加。
一个容易误会的地方：打开程序不是把整个文件机械地一次性搬进 RAM
现代操作系统常使用虚拟内存、按需加载、内存映射、页缓存等机制。程序所需的部分内容可能逐步载入，未必在启动瞬间把所有字节都读入物理内存。

所以，正确的入门理解是：程序的执行需要合适的内存映射和运行环境，操作系统负责协调这些工作，而不是「整个软件先原封不动地复制到 RAM，CPU 再开始读」。
六、双击一个程序后，发生了什么？
我们现在可以把开头的问题拆开。这是一次典型桌面应用启动过程的概念化描述，细节会因 Windows、macOS、Linux 和程序类型而异。
第一步：鼠标把操作变成输入事件
鼠标将移动、点击等信息通过设备接口传递给计算机；操作系统和图形界面相关组件接收并处理事件。

你双击图标，图形界面判断你想启动某个应用。
第二步：系统定位程序与必要资源
系统需要知道程序对应的可执行文件在哪里，可能还要读取配置、共享库及其他依赖。

这里就用到了上一课的内容：文件、路径、目录和文件系统。
第三步：操作系统创建运行环境
它为新程序创建进程，并建立必要的地址空间、内存映射、权限与资源管理信息。需要执行的代码和相关数据随后能够被访问。

你可以暂时把**进程（process）**理解成「一个正在执行、由操作系统管理的程序实例」。同一个应用也可能使用多个进程。
第四步：CPU 开始执行程序指令
CPU 根据系统安排，逐步执行与程序有关的机器指令。它会使用寄存器、缓存、内存，并根据需要进行分支、计算和数据处理。
第五步：程序请求显示窗口
应用通常通过操作系统与图形相关的 API、窗口系统或图形框架，完成窗口创建和内容绘制。GPU 可能参与绘制，显示设备最后把图像呈现给你。

于是，你看见浏览器窗口。
双击图标
   ↓
输入事件被处理
   ↓
定位可执行文件与依赖
   ↓
创建进程和运行环境
   ↓
CPU 执行指令，程序访问数据
   ↓
通过图形系统输出到屏幕
这不是说启动过程只发生六个动作。恰恰相反，这六个阶段帮助我们把极其复杂的事情分层理解。
七、为什么一台电脑能同时运行很多软件？
你可能一边浏览网页、一边播放音乐、同时还在下载文件。难道 CPU 同一时刻真的在执行所有程序吗？

答案要分情况：
- 对单个 CPU 核心而言，操作系统可以快速切换不同任务，让它们轮流获得执行机会。
- 多核心 CPU 可以在不同核心上并行执行不同任务。
- 程序中还有线程、等待设备完成操作等机制，让「同时运行」变得更复杂也更高效。
操作系统的调度机制负责决定哪些任务何时得到处理器时间。它还需要管理内存、隔离进程以及协调设备访问。

所以，「某个软件卡住了，但其他软件还能用」并不神秘：现代操作系统通过进程隔离和调度等机制，尽可能让不同应用互不干扰。当然，如果整个系统资源耗尽或驱动、内核发生严重故障，其他程序也可能受到影响。
八、总线是什么？数据怎么在硬件之间流动？
计算机的各个部件并非靠魔法交换数据。它们通过电路、控制器和不同类型的互连机制通信。

在入门课程里，你可能会看到**总线（bus）**这个词：它泛指某类能够在组件之间传递信息的共享通信通路或通信机制。

传统教材经常讲：
- 数据总线传递数据。
- 地址总线表达要访问哪里。
- 控制总线传递控制信号。
这种分类有助于理解硬件通信的不同需求。但现代电脑还使用更复杂的点对点互连、串行总线和控制器，例如 PCIe 等，不能把整台计算机想象成只有三根线。

你只需理解：CPU、内存、存储与外设通过明确的接口和通信机制配合，并非所有部件都直接互相读取对方内部的数据。
九、为什么有的电脑更快？
购买电脑时，你经常看到 CPU 主频、核心数、内存大小、SSD 速度等参数。

但「快」并不由单一数字决定。
- 打开大型程序，可能受存储读取、内存、CPU 和软件实现等因素共同影响。
- 大量数据计算，可能受 CPU 性能、缓存效率、内存带宽等因素影响。
- 游戏和图形工作，可能明显依赖 GPU 与显存等资源。
- 同时打开太多程序，可能发生内存压力，导致频繁换页和响应变慢。
因此，不是 CPU 主频越高就一定越快，也不是硬盘越大电脑就越快。要看你执行什么任务、任务的瓶颈在哪里。

这里不要求你挑选硬件型号，只希望你开始形成「不同任务依赖不同资源」的判断方式。
十、这些原理为什么能帮助你理解 AI 编程工具？
当 Claude Code、Codex 等工具要求「运行测试」时，背后通常需要启动真实的程序或命令。此时操作系统会创建进程，CPU 执行指令，内存承载运行状态，文件系统则存放源代码、依赖和测试结果。

如果一个构建命令执行失败，原因可能是：
- 找不到需要的文件或依赖。
- 没有足够权限。
- 内存或磁盘空间不足。
- 程序自身存在错误。
- 网络不可用，导致依赖下载失败。
理解计算机如何工作，能让你在看到这些问题时，至少知道该往哪个方向调查，而不是只会反复让 AI「再试一次」。

另外，工具请求执行命令，并不意味着它应该自动获得所有权限。操作系统的权限边界和你的审查仍然重要。
十一、动手观察：你的电脑正在做什么？
本次实验不需要安装软件，也不需要运行陌生命令。
Windows
按 Ctrl + Shift + Esc 打开任务管理器。在「进程」或「性能」页面观察 CPU、内存、磁盘的使用情况。
macOS
打开活动监视器（Activity Monitor），观察 CPU、内存和磁盘等页面。
常见 Linux 桌面
打开系统自带的**系统监视器（System Monitor）**或同类工具。不同桌面环境的软件名称可能不同。
试着做三件事
1. 保持监视器开启，再启动一个你常用的应用，观察 CPU 和内存指标是否变化。
2. 在应用启动与正常使用时，比较资源占用的变化。
3. 关闭应用，观察资源使用是否变化。某些后台进程和缓存可能仍然保留，因而不必期待所有数字立即归零。
不要通过结束陌生的系统进程来做实验。这里只需要观察。

最后记下三句话：
我启动的程序：________
启动时发生变化的资源：________
我认为变化的原因：________
这就是一次最简单的系统观察实验。
十二、理解检查：你能回答吗？
1. 程序保存在 SSD 上，为什么运行时还要使用内存？
2. CPU 真的理解「打开网页」这样的自然语言需求吗？它实际执行什么？
3. 取指—译码—执行是帮助理解的模型，为什么不能把它当成所有现代 CPU 的完整工作方式？
4. 进程和磁盘上的程序文件是同一回事吗？
5. 电脑同时运行多个应用，背后可能用了哪些机制？
6. 为什么内存容量变大，不必然意味着所有软件都会按比例变快？
如果有的问题答不上来，可以回看对应的小节。理解不同部件如何分工，比记住缩写更重要。
小结：从一次双击，看见整台计算机
当你再次双击某个图标时，可以试着在脑海里还原这个过程：
1. 输入设备让计算机接收到你的操作。
2. 操作系统定位程序，建立运行环境并管理资源。
3. 文件系统与存储设备提供程序和数据。
4. 内存让运行中的程序能够高效访问必要信息。
5. CPU按指令集规则执行机器指令。
6. 输出系统最终将结果呈现在屏幕上。
计算机并不是一块无所不能的芯片，而是不同部件与不同层次的软件相互协作的系统。
